# 安全边界

这个项目把「AI Agent 修改 Figma 文档」的能力暴露给本机进程。默认配置已经尽量收紧，
但仍不是沙箱，请按自己的风险模型使用。

## 中继

- 只监听 `127.0.0.1:3055`（可用 `FIGMA_RELAY_HOST` 改，但不建议暴露到局域网）。
- **无 TLS、无鉴权、无 Origin 校验**。频道名只是路由标识，不是秘密。
- 本机任意进程都能连接中继；浏览器页面也可能连接 `ws://127.0.0.1:3055`
  （WebSocket 不受同源策略限制）。知道/猜到频道名的页面理论上可以尝试调用插件命令。
- 建议：
  - 不用时关掉中继；
  - 不要把端口转发到公网；
  - 在独立 Figma 文件里做自动化，不要直接对生产设计稿操作；
  - 需要更强隔离时，在中继前加一层 token 校验或 Origin 白名单（当前未实现）。

## 插件

- 插件以当前用户权限运行，能读取和修改打开的文件。
- 插件不是只读的：拿到频道的外部程序可以调用 `create_*`、`delete_node`、
  `set_text_content` 等命令。
- 本仓库移除了上游的 Google Analytics 上报，插件不会主动向第三方发送数据。

## MCP server

- 通过 stdio 与宿主客户端通信，默认连接 `ws://localhost:3055`。
- MCP 工具列表包含删除、覆盖类操作；是否自动执行由客户端权限模式决定。
  建议在需要人工确认的客户端里开启确认（例如 plan / ask 模式）。

## 数据

- 中继日志会记录频道名、命令名和命令 id，不记录命令参数内容。
- 如果你把命令参数写进 shell 历史，注意其中可能包含文档内容。
